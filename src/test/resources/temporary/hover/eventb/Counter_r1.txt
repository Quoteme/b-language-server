---

The dynamic part of a model: variables, invariants and the events that change the variables. A machine can refine one machine and see contexts.

**Example**
```eventb
machine Counter sees Limits
variables n
invariants
  @inv1 n ∈ 0 ‥ limit
events
  event INITIALISATION
    then @act1 n ≔ 0
  end
  event inc
    when @grd1 n < limit
    then @act1 n ≔ n + 1
  end
end
```

=== #f6a950d2d69a
```eventb
x ≔ E
```

---

**Deterministic assignment** · Typed as `:=`.

x1,…,xn ≔ E1…,En assigns the expressions Ei to the variable xi, with i ∈ 1‥n. All xi must be distinct identifiers that refer to variables of the concrete machine.

There is a special form of the assignment which uses a relational overwrite:

x(F) ≔ E.

*Definition:* The before-after-predicate of x1,…,xn ≔ E1,…,En is; x(F) ≔ E ≙ x ≔ x {F ↦ E}  
*Type:* xi and Ei must have the same type: xi ∈ αi and Ei ∈ αi for i ∈ 1‥n.  
*Well-definedness:* L(x1,…,xn ≔ E1,…,En) ≙ L(E1) ∧ … ∧ L(En); L(x(F) ≔ E) ≙ L(F) ∧ L(E)

**Example**
```eventb
@act1 n ≔ n + 1
@act2 f(1) ≔ 2
```

[Rodin Handbook, 3.3.8.1 Deterministic Assignments](https://www3.hhu.de/stups/handbook/rodin/current/html/assignments.html#deterministic_assignments)

=== #faae401f9814

---

**Addition** · Typed as `+`.

These are the usual arithmetic operations.

*Definition:* amod b = c ≙ c ∈ 0‥b-1 ∧ ∃ k · k ∈ ℕ ∧ k · b + c = a  
*Type:* a + b ∈ ℤ  
*Well-definedness:* L(a + b) ≙ L(a) ∧ L(b)

**Example**
```eventb
2 + 3 = 5
```

=== #2245788fc758
```eventb
E = F
```

---

**Equality** · Typed as `=`.

Checks if both expressions are or are not equal.

*Definition:* E ≠ F ≙ ¬ (E = F)  
*Type:* E = F and E ≠ F are predicates with E ∈ α and F ∈ α, i.e. E and F must have the same type.  
*Well-definedness:* L(E = F) ≙ L(E) ∧ L(F)

**Example**
```eventb
{1, 2} = {2, 1}
```

[Rodin Handbook, 3.3.2.4 Equality](https://www3.hhu.de/stups/handbook/rodin/current/html/predicates.html#equality)
